Which audience, channel and message should a marketer test next?

SignalLoop is a working prototype that turns campaign evidence into a recommendation for the next experiment: who to reach, where, with which message, and why. I built it to test a hypothesis: as AI makes content cheap to produce, the harder marketing problem is deciding what to create next.

What SignalLoop does

Code measures results. One AI agent recommends the next test and cites its evidence; another writes the variant. A marketer approves each step, and every test runs against the best version so far.

What it demonstrates

Where PMM judgment, deterministic analysis and AI each belong in a marketing decision, and how to constrain AI so its recommendations can be checked.

The problem I wanted to investigate

If content is cheap to make, is deciding what to make the real bottleneck?

Generative AI lowers the cost of producing another email, post or landing page. My hypothesis is that this moves the hard part of product marketing upstream, to choosing which experiment deserves the next asset.

Which audience × channel × message combination deserves the next experiment?

Answering that well means holding three questions at once:

Who is responding?

Compare audiences across every channel they use, not one channel at a time.

Is the difference real?

Separate a gap worth acting on from noise in a small sample.

What hasn't been tried?

Build on what was already tested instead of starting each campaign from scratch.

This is a hypothesis, not a validated finding. See what I want to validate.

How SignalLoop makes the decision

Each part of the decision has a clear owner.

The marketer sets the rules and approves. Code measures. AI interprets the evidence and writes the variant.

The marketer

  • Defines segments, messaging angles and brand rules
  • Sets the campaign objective
  • Approves the recommendation before content is written
  • Approves the content before the test runs

The system

  • Measures results and checks significance (code)
  • Recommends the next test, citing evidence (Marketing Agent)
  • Plans and writes the variant (Content Agent)
  • Tests it against the best version so far and records the result
One decision, end to end

A Ramp scenario, from evidence to the next action

One run of the demo, recorded step by step. Performance numbers are SIMULATED. The recommendation, hypothesis and email are the agents' AI output from that run (Gemini), shown as written unless marked condensed.

  1. Context
    INPUT

    Ramp scenario with three role-based segments. Campaign objective: product consideration, which favors response rate over reach. A baseline sent each audience its original message on every channel it uses.

  2. Evidence
    CODESIMULATED

    Controllers responded best: 9.8% CTR (151 clicks from 1,548 reached), 4.5 points above the other audiences. For Controllers, email had the highest CTR (14.6%), while LinkedIn delivered more clicks per experiment (63 vs 35). Only one messaging angle, time savings, had been tested with them.

  3. Insight
    CODE

    Two openings: a reach-versus-response trade-off between LinkedIn and email, and three untested messaging angles for the best-responding audience.

  4. Decision
    AI · MARKETING AGENTMARKETER APPROVES

    Reach Controllers on email with a real-time visibility message, as a customer story. The agent labeled it "trying something new" with medium confidence, and named the trade-off: fewer clicks than LinkedIn, in exchange for the stronger response the objective favors.

  5. Hypothesis
    AI

    A real-time visibility customer story by email will drive higher engagement from Controllers than the current time-savings how-to guide. (condensed)

  6. Content
    AI · CONTENT AGENTMARKETER APPROVES

    Subject: "Stop waiting for the month-end surprise". Preview text: "Gain total visibility into company spend as it happens." Button: "See how it works." Automated checks reject numbers, placeholder links and off-channel personalization before the marketer sees it.

  7. Experiment
    CODEDELIVERY SIMULATED

    Controllers on email, split 50/50: the new email against the best version so far, "Close the books without chasing receipts" (time savings, how-to guide). Nothing was sent.

  8. Result
    SIMULATEDCODE

    New email 7.3% (9 of 124 reached) vs best so far 11.8% (14 of 119): 4.5 points lower, but on 23 clicks in total. Verdict: too close to call. SignalLoop calls a winner only with at least 20 clicks on each side and a statistically significant gap.

  9. Next action
    CODEAI

    No loser is declared. The best-so-far email stays the control, the test is recorded as inconclusive, and the next recommendation receives it as uncertainty: the Marketing Agent is instructed to retest or try an untested angle, not to treat the result as a loss.

A results dashboard would show the new email losing by 4.5 points. SignalLoop holds that conclusion until the evidence supports it: the kind of judgment I wanted built into the system rather than left to chance.

The decisions behind the design

The trade-offs a PMM should be able to check

Decision 1

Code calculates every metric. AI only reads the results.

Why
A recommendation is only as trustworthy as its numbers. Code gives the same answer every time, so any figure can be audited; language models are unreliable at arithmetic and can find patterns that aren't there.
Alternative considered
Letting the model analyze raw campaign data. Faster to build and more flexible, but its conclusions couldn't be checked.
Decision 2

Strategy and content are separate AI steps.

Why
It mirrors how a PMM reviews a test plan before any copy exists. The Marketing Agent decides who, where and why; the Content Agent can't change those choices, only execute them.
Alternative considered
One agent that plans and writes in a single pass. Cheaper, but strong copy can hide a weak strategic choice.
Decision 3

No recommendation without evidence.

Why
Every recommendation must cite metrics the agent actually retrieved, and code rejects anything else. A PMM should be able to trace a recommendation to its numbers before acting on it.
Alternative considered
Free-form reasoning. More fluent, but a confident wrong answer would look the same as a right one.
Decision 4

A marketer approves every step.

Why
Positioning, claims and budget carry accountability that should stay with a person. The recommendation is approved before content is written, and the content before the test runs.
Alternative considered
A fully autonomous loop. Faster, but it removes the review where marketing judgment matters most.
Decision 5

Every test runs against the best version so far.

Why
"Did it work?" needs a comparison. The new variant and the current best share an audience and channel, split 50/50, and a winner is called only with 20+ clicks on each side and a significant gap.
Alternative considered
Comparing against a historical average. Simpler, but it mixes timing and audience effects, and the loop would learn from noise.
Decision 6

Each company example uses a different segmentation model.

Why
To test whether the same decision logic adapts when a market is structured differently: by role in one scenario, by business stage in the other. See the models.
Alternative considered
One generic persona set. Easier to demo, but it would hide whether the logic depends on a particular market structure.
Decision 7

Campaign performance is simulated; the CRM integration is real.

Why
A portfolio prototype has no real audience or budget. A hidden response model lets the full loop run with outcomes the agents can't see in advance, while real HubSpot writes show the workflow connects to an actual marketing system. The prototype tests the decision workflow, not marketing results.
Alternative considered
Public benchmarks or illustrative results. Benchmarks wouldn't respond to the system's choices, and invented results would misrepresent what was shown. Every simulated number here is labeled.
Segmentation models used for this demonstration

Two market structures, modeled on purpose

Ramp and Square are illustrative scenarios. The segments below are my assumptions, chosen for this demonstration. They are not either company's segmentation, and no internal data or research informed them.

Ramp scenario

Role-based model · assumption

Why this structure: spend management involves different people with different jobs, from the budget owner to the person closing the books to the employee making a purchase.

  • Finance Leaders: own budget, forecasting and financial control
  • Controllers: responsible for an accurate, on-time close
  • Employee Spenders: buy software, travel or supplies to do their jobs

Square scenario

Business-stage model · assumption

Why this structure: an owner-operator often holds every role, so needs change more with the business's maturity than with job title.

  • New Sellers: taking their first payments
  • Growing Businesses: steady sales, in person and online
  • Multi-Location Operators: several sites run as one business
Same logic, different answers: simulated baselines for both models

Each scenario's segments, channels and messaging angles live in one company-profile file; the decision logic is shared.

    How it's built

    For technical reviewers

    The case study doesn't depend on these details. They show how the constraints described above are enforced.

    Architecture
    PageStatic case study and demo. Opening the page makes no API calls; only running a step does.
    APINetlify Functions for running an experiment, getting a recommendation, creating content and starting over, with rate limits and daily caps.
    ModelsGroq (openai/gpt-oss-120b) first, with Gemini (gemini-3.1-flash-lite) as the fallback when Groq is rate-limited or fails.
    CRMHubSpot API: fictional contacts, a persona property and one audience list per segment.
    StorageNetlify Blobs for each visitor's experiment history.
    How the agents are constrained

    Marketing Agent

    • Reads metrics only through read-only tools
    • Must cite 2 to 5 metrics it actually retrieved
    • The channel must be available to the chosen audience
    • The test must differ from the current best version
    • Confidence capped at medium before three experiments

    Content Agent

    • Cannot change the audience, channel or messaging angle
    • No numbers or statistics, so no unverifiable claims
    • Can't reuse a topic already tested with the audience
    • Personalization by first name only, and only in email
    • No links or placeholders; the call to action is a button

    Output that fails a check is sent back once with the errors, then to the fallback model, and otherwise fails visibly. Unchecked output is never shown.

    Statistics
    • A winner is called only with at least 20 clicks on each side and a two-proportion z-test at about 95% confidence (|z| ≥ 1.96).
    • Efficiency leader = highest CTR. Volume leader = most expected clicks per experiment. The campaign objective decides which matters more.
    • Audience results are pooled across experiments and compared with the other audiences.
    Simulated performance model

    Each audience has a hidden response profile by channel, messaging angle and content type, with random variation in every run. The agents see only measured results, so a good recommendation has to be inferred from evidence.

    Before production

    What would need to be true before a team relied on this

    • Real performance data. Actual email, social and web engagement in place of the simulator.
    • Pipeline and revenue signals. Experiments judged by downstream impact, not clicks alone.
    • Stronger experiment design. Sample sizes and test durations set in advance.
    • Governance. Approval roles, brand and legal review, and an audit trail of every recommendation.
    • Organizational context. Positioning, launch calendars and sales priorities the agents can't see today.

    What this project shows

    How I approach AI in product marketing: start from the decision that matters, separate evidence from judgment, let code own what should be deterministic, use AI where interpretation adds value, and keep a marketer accountable for the call.

    SignalLoop works as software. Whether it earns a place in a real PMM workflow is the next question, and I'm taking it to the people who make these decisions.
